AuthEndpoints maps ready-made auth API endpoints on top of ASP.NET Core Identity. It is for a first-party API: your own web and mobile clients (React, Next.js, Vue, Nuxt, Svelte, or native apps) signing in to your own backend. You keep Identity, your user type, and EF Core. AuthEndpoints adds the routes, the rate limits, the CSRF checks, and the step-up flow that you would otherwise write by hand.

Coming from `MapIdentityApi`? See [MapIdentityApi alternative](/concepts/mapidentityapi-alternative) for logout, chosen routes, JWT, and passkeys.

## What AuthEndpoints can do

| Capability | What it does | Guide |
| --- | --- | --- |
| Email and password registration | Creates accounts and sends a confirmation email. | [Register users](/guides/registration) |
| Passkey registration | Creates passwordless accounts with WebAuthn. | [Register users](/guides/registration#register-with-a-passkey) |
| GitHub and Google | Adds social sign-up and sign-in. Compose it. The facades do not map it. | [Register users](/guides/registration#register-with-github-or-google) |
| Cookie sessions | Signs browser users in with the Identity application cookie. | [Sign users in](/guides/sign-in) |
| Identity bearer tokens | Issues access and refresh tokens for native and mobile apps. | [Sign users in](/guides/sign-in#sign-in-with-a-password-and-identity-bearer-tokens) |
| JWT with a refresh cookie | Issues short-lived JWTs with rotating, hashed refresh tokens. | [Sign users in](/guides/sign-in#sign-in-with-a-password-and-a-jwt) |
| Passkey sign-in | Signs users in with a passkey. | [Sign users in](/guides/sign-in#sign-in-with-a-passkey) |
| Two-factor authentication | Turns on authenticator codes and 10 recovery codes. | [Turn on two-factor authentication](/guides/two-factor) |
| Password reset | Sends reset codes and sets a new password. | [Reset a forgotten password](/guides/reset-password) |
| Email and password change | Changes the email after the user confirms the new address. | [Change a user's email or password](/guides/manage-account) |
| Passkey management | Adds, renames, and removes passkeys. | [Add, rename, and remove passkeys](/guides/manage-passkeys) |
| Account linking | Links and unlinks GitHub or Google logins. | [Link and unlink GitHub or Google accounts](/guides/link-external-accounts) |
| Step-up (ReAuth) | Asks for proof again before sensitive changes. | [Require step-up before sensitive actions](/guides/step-up) |
| Built-in protection | Adds CSRF checks, rate limits, lockout, and startup checks. | [Security model](/concepts/security-model) |
| Composable modules | Maps only the routes you need, on your own prefixes. | [Composable endpoints](/composables) |

## Facade or composition

Most new hosts start with the password facade: `AddPasswordAuth`, `UseAuthEndpoints`, and `MapPasswordAuth`. It maps password sign-up, sign-in, recovery, and account management under `/auth`. Cookie is the default session. JWT is the other session. Passkeys are included when `Passkeys.ServerDomain` is set. See [Password auth](/getting-started/password-auth).

`AddAuthEndpoints`, `UseAuthEndpoints`, and `MapAuthEndpoints` stay the 3.4.1 compatibility facade: Identity management and one sign-in stack under `/identity`, passkeys under `/account`, and optional JWT under `/auth`. External OAuth is never part of either facade. Do not call both facades in one host.

| Approach | Use it for |
| --- | --- |
| Password facade, cookie | Browser clients. This is the default for new hosts. |
| Password facade, JWT | A JWT session, including body refresh for native clients. Set `Session` to `Jwt`. |
| 3.x facade, cookie | Existing hosts, and the [quick start](/getting-started/quick-start). |
| 3.x facade, Identity bearer | Native and mobile clients on `AddAuthEndpoints`. Pass `AuthEndpointsSignIn.IdentityBearer`. |
| Composition | A custom mix, email-code sign-in, or more than one session. |

To pick a stack, see [Choose a sign-in stack](/getting-started/choose-a-sign-in-stack). To build one by hand, see [Composable endpoints](/composables).

GitHub and Google sign-in ships in `AuthEndpoints.OAuth.GitHub` and `AuthEndpoints.OAuth.Google` 4.0.0. Those packages register the handlers. The endpoints are in the core package. Neither facade maps them. See [External OAuth](/modules/external-oauth).

## Requirements

- .NET 10
- ASP.NET Core Identity
- EF Core for the user store
