AuthEndpoints maps ready-made auth API endpoints on top of ASP.NET Core Identity. It is for a first-party API. Your own web and mobile clients sign in to your own backend. You keep Identity, your user type, and EF Core. AuthEndpoints adds the routes, the rate limits, the CSRF checks, and the step-up flow.

The home page lists [what AuthEndpoints can do](/#what-authendpoints-can-do). The task list is [I want to](/guides#i-want-to).

## One fast path

Most new hosts start with the password facade. [Quick start](/getting-started/quick-start) goes from an empty project to cookie sign-in with `AddPasswordAuth`, `UseAuthEndpoints`, and `MapPasswordAuth`.

When that setup is not the one you need, open [Pick your setup](/getting-started/choose-a-sign-in-stack). The table there matches a need to one call and one page: cookie or JWT, passkeys, an emailed code, GitHub or Google, or a custom mix of `Add*` and `Map*` pairs.

`AddAuthEndpoints` and `MapAuthEndpoints` stay the [3.x facade](/getting-started/compatibility-facade). Do not call both facades in one host. A host that already uses the 3.x facade follows [Upgrade to 4.0](/guides/upgrading-to-4).

## Facade or composition

A facade is one fixed composition. The password facade maps password sign-up, sign-in, recovery, and account management under `/auth`. The 3.x facade maps management and one sign-in stack under `/identity`, passkeys under `/account`, and optional JWT under `/auth`.

Composition is the same building blocks with the prefixes and the mix you choose. The pairs are in the [composition table](/composables/composition). Why the blocks split that way is in [How composition works](/composables).

GitHub and Google sign-in ships in `AuthEndpoints.OAuth.GitHub` and `AuthEndpoints.OAuth.Google` 4.0.0. Those packages register the handlers. The endpoints are in the core package. Neither facade maps them.

## Requirements

- .NET 10
- ASP.NET Core Identity
- EF Core for the user store
