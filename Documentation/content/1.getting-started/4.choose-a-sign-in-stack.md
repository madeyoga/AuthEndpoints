Start with the [quick start](/getting-started/quick-start) when a browser signs in with a password and a cookie. Use this page when that is not the setup you need.

The password facade is `AddPasswordAuth` and `MapPasswordAuth`. It maps one session under `/auth`. Cookie is the default. JWT is the other session. It does not map email-code sign-in or external sign-in. The 3.x facade is `AddAuthEndpoints` and `MapAuthEndpoints`. Do not call both in one host.

| You need | Call | Page |
| --- | --- | --- |
| Password sign-in for a browser, with a cookie | `AddPasswordAuth`. Leave `Session` at `Cookie`. | [Quick start](/getting-started/quick-start) |
| A JWT session | `Session` = `Jwt`, and a `Jwt` callback. | [Password auth](/getting-started/password-auth), [JWT](/modules/jwt) |
| A native client that stores the refresh token | JWT, and `RefreshTokenTransport.Body`. | [JWT](/modules/jwt#options) |
| Identity bearer tokens | `AddAuthEndpoints` with `AuthEndpointsSignIn.IdentityBearer`. | [3.x facade](/getting-started/compatibility-facade), [Bearer auth](/modules/bearer-auth) |
| Passkeys beside passwords | Set `Passkeys.ServerDomain` on the password facade. | [Passkeys](/modules/passkeys), [Register users](/guides/registration#register-with-a-passkey) |
| Passkey login, and no public passkey register | `MapSignInEndpoints` with `AddPasskeySignInEndpoints` only. | [Passkeys](/modules/passkeys#map) |
| An emailed code | `AddEmailCodeEndpoints`. Sign-up and the magic link default to off. | [Sign in with an emailed code](/guides/email-code) |
| GitHub or Google | A provider package, then `MapExternalAuthEndpoints`. | [Register users](/guides/registration#register-with-github-or-google) |
| No public sign-up | Compose sign-in, and do not map register or external sign-in. | [Run an app with no public sign-up](/guides/internal-app) |
| More than one session, or a custom mix | The `Add*` and `Map*` pair for each module. | [Composition table](/composables/composition), [Recipes](/composables/recipes) |
| An existing 3.x host | Keep `AddAuthEndpoints`. | [Upgrade to 4.0](/guides/upgrading-to-4), [3.x facade](/getting-started/compatibility-facade) |

## Turn passkeys on

On the password facade, passkeys stay off until `Passkeys.ServerDomain` is a non-empty domain. That setting maps passkey sign-in and passkey management on the same prefix. Sign-in includes `POST /passkeys/register`, which creates an account. To map passkey login without that register route, follow [Passkeys](/modules/passkeys#map).

On the 3.x facade, passkeys are on until you set `Passkeys.Enabled` to `false`. Production then requires `Passkeys.ServerDomain`.

## Add an emailed code

The password facade does not map email-code routes. Call `AddEmailCodeEndpoints` and map `MapEmailCodeEndpoints` on the prefix you choose. `AllowSignUp` defaults to `false`, so an unknown address does not become an account. `MagicLink.Enabled` defaults to `false`. The 3.x facade maps the same routes when `EmailCode.Enabled` is `true`.

## Add GitHub or Google

Install `AuthEndpoints.OAuth.GitHub`, `AuthEndpoints.OAuth.Google`, or both. Register the handler, then map `MapExternalAuthEndpoints` or `MapExternalAuthProvider`. Neither facade maps those routes.

A verified provider email creates an account when no local user has that email. There is no option to stop that. `RequireVerifiedEmail` defaults to `true` and refuses an unverified email. It does not stop creation for a verified email. See [External OAuth](/modules/external-oauth#security-behavior).

## Compose the pairs

Call the `Add*` method before the matching `Map*`. A missing `Add*` throws `InvalidOperationException`. The messages are in [How composition works](/composables#what-you-compose). The pairs, the routes, and which facade contains each pair are in the [composition table](/composables/composition). Copy-paste hosts are in [Recipes](/composables/recipes).
