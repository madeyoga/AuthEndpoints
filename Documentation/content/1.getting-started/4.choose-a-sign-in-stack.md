Start with the [quick start](/getting-started/quick-start) when a browser signs in with a password and a cookie. Use this page when that is not the setup you need.

`AddAuthEndpoints` returns a builder. Add the sign-in methods you want, then `MapAuthEndpoints` maps them and one session under one prefix. It does not map external sign-in.

| You need | Call | Page |
| --- | --- | --- |
| Password sign-in for a browser, with a cookie | `AddAuthEndpoints().AddPassword()`, mapped with `AuthEndpointsSession.Cookie`. | [Quick start](/getting-started/quick-start) |
| A JWT session | `.AddJwt(...)`, mapped with `AuthEndpointsSession.Jwt`. | [AddAuthEndpoints](/modules/add-auth-endpoints), [JWT](/modules/jwt) |
| A native client that stores the refresh token | JWT, and `RefreshTokenTransport.Body`. | [JWT](/modules/jwt#options) |
| Identity bearer tokens | `.AddIdentityBearer()`, mapped with `AuthEndpointsSession.IdentityBearer`. | [Bearer auth](/modules/bearer-auth) |
| Passkeys beside passwords | `.AddPasskeys(p => p.ServerDomain = "example.com")`. | [Passkeys](/modules/passkeys), [Register users](/guides/registration#register-with-a-passkey) |
| Passkey login, and no public passkey register | `.AddPasskeys(p => p.SignUp = false)`. | [Passkeys](/modules/passkeys#map) |
| An emailed code | `.AddEmailCode()`. Sign-up and the magic link default to off. | [Sign in with an emailed code](/guides/email-code) |
| GitHub or Google | A provider package, then `MapExternalAuthEndpoints`. | [Register users](/guides/registration#register-with-github-or-google) |
| No public sign-up | Compose sign-in, and do not map register or external sign-in. | [Run an app with no public sign-up](/guides/internal-app) |
| More than one session, or a custom mix | The `Add*` and `Map*` pair for each module. | [Composition table](/modules/composition), [Build a custom auth stack](/composables#copy-a-host) |

## Turn passkeys on

Call `.AddPasskeys()` on the builder and set `ServerDomain`. That maps passkey sign-in, passkey sign-up, and passkey management on the same prefix. Sign-up is `POST /passkeys/register`, which creates an account. To map passkey login without that register route, set `SignUp = false`. See [Passkeys](/modules/passkeys#map).

## Add an emailed code

Call `.AddEmailCode()` on the builder. `MapAuthEndpoints` then maps send, verify, and email-code step-up. A composed host calls `AddEmailCodeEndpoints` and maps `MapEmailCodeEndpoints` on the prefix it chooses. `AllowSignUp` defaults to `false`, so an unknown address does not become an account. `MagicLink.Enabled` defaults to `false`.

## Add GitHub or Google

Install `AuthEndpoints.OAuth.GitHub`, `AuthEndpoints.OAuth.Google`, or both. Register the handler, then map `MapExternalAuthEndpoints` or `MapExternalAuthProvider`. `MapAuthEndpoints` does not map those routes.

A verified provider email creates an account when no local user has that email. There is no option to stop that. `RequireVerifiedEmail` defaults to `true` and refuses an unverified email. It does not stop creation for a verified email. See [External OAuth](/modules/external-oauth#security-behavior).

## Compose the pairs

Call the `Add*` method before the matching `Map*`. A missing `Add*` throws `InvalidOperationException`. The messages are in [What you compose](/composables#what-you-compose). The pairs, the routes, and the maps that contain each pair are in the [composition table](/modules/composition). Copy-paste hosts are in [Build a custom auth stack](/composables#copy-a-host).
