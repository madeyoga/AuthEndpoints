## Does this replace ASP.NET Core Identity?

No. AuthEndpoints maps endpoints on top of Identity. You keep Identity, your user type, and EF Core.

## Cookie sessions or JWT?

Both are available, and so is Identity bearer. Cookies are the default for browser apps on the password facade. See [Choose your sign-in setup](/getting-started/choose-a-sign-in-stack).

## Are passkeys included?

Yes. The core package includes passkey registration, sign-in, and management. The password facade maps them when `Passkeys.ServerDomain` is set. Passkey sign-in skips two-factor authentication. See [Passkeys](/modules/passkeys) and [Security model](/concepts/security-model#two-factor-is-a-password-add-on).

## How does 2FA work?

AuthEndpoints uses Identity's authenticator (TOTP) 2FA and 10 recovery codes. Changing 2FA settings requires step-up ReAuth. See [Turn on two-factor authentication](/guides/two-factor).

## Can I map only some of the endpoints?

Yes. Start with the password facade, then compose modules on your own prefixes when you need a custom path or a JWT-only API. See [Build a custom auth stack](/composables).

## Can users sign in with GitHub or Google?

Yes, with `AuthEndpoints.OAuth.GitHub` and `AuthEndpoints.OAuth.Google`. You map their routes yourself. See [Register users](/guides/registration#register-with-github-or-google).

## Can this be my Sign in with Google provider for other apps?

Yes, with the opt-in `AuthEndpoints.OpenIddict` package (preview). The core package signs users in to your own app only. `AuthEndpoints.OpenIddict` turns your app into an OAuth 2.0 authorization server and, with the `openid` scope, an OpenID Connect provider, built on OpenIddict. Other apps, CLIs, and MCP clients send users to your app, the users approve on your consent page, and the clients get access, refresh, and ID tokens. See [OAuth server (OpenIddict)](/modules/openiddict). For what it adds over plain OpenIddict, and when to use a full identity server instead, see [vs OpenIddict](/concepts/compare#vs-openiddict).

## Does MapIdentityApi include a logout endpoint?

No. .NET 10 `MapIdentityApi` does not map `/logout`. The Identity API article shows a `/logout` route you add yourself that calls `SignInManager.SignOutAsync()`. That signs out the application cookie, and the external and two-factor user-id schemes when they are registered. It does not revoke Identity bearer access or refresh tokens. AuthEndpoints maps logout on each sign-in stack. Cookie `POST /auth/logout` requires a signed-in user and a CSRF token, and it clears the application, external, two-factor, remember-client, and ReAuth cookies. Identity bearer `POST /auth/logout` clears those cookies and leaves the bearer tokens valid until they expire. JWT `POST /auth/logout` revokes the refresh-token family and deletes the refresh cookie. The JWT access token stays valid until it expires. See [Sign users out](/guides/sign-out).

## Can I map only some MapIdentityApi routes or rename them?

`MapIdentityApi` maps its full set in one call. `MapGroup` adds one prefix to every route. It cannot omit a route or rename `/login`. AuthEndpoints splits that surface into `MapIdentityManagementApi`, `MapCookieAuthEndpoints`, `MapBearerAuthEndpoints`, `MapJwtAuthEndpoints`, and `MapPasskeyEndpoints`. Map the modules you need. Set the prefix with `MapGroup`, or with `Path` on the password facade. The segment under that prefix stays fixed (`/login`, `/register`, `/logout`). A module does not let you drop one of its routes. See [Build a custom auth stack](/composables).

## Does MapIdentityApi return a JWT?

No. Login without `useCookies` or `useSessionCookies` returns Identity bearer tokens. They are data-protection tickets, not JWTs. Those query flags issue the application cookie instead of a token body. AuthEndpoints can issue the same Identity bearer tokens, the application cookie (the password facade default), or a separate JWT. The JWT is an access token in the response plus an HttpOnly refresh cookie. Refresh tokens are stored as hashes, rotated on use, and revoked as a family if an old token is reused. See [Choose your sign-in setup](/getting-started/choose-a-sign-in-stack).

## Does MapIdentityApi include passkey endpoints?

No. .NET 10 `MapIdentityApi` does not map passkey routes. The Blazor Identity template has its own passkey pages. Those are not `MapIdentityApi`. AuthEndpoints maps passkey registration, sign-in, and management. The password facade maps them under `/auth/passkeys` only when `Passkeys.ServerDomain` is set. Passkey sign-in skips two-factor authentication. See [Passkeys](/modules/passkeys).
