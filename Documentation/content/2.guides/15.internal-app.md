Create accounts in your own admin code. Do not map a public register route.

`AddPasswordAuth` always maps `POST /register`. There is no option to turn that route off. Compose sign-in instead.

## Map sign-in without register

1. Call `AddAuthEndpointsIdentity`. It sets `RequireConfirmedAccount` to `true`, then runs your callback.
2. Register password sign-in, recovery, account management, and the cookie session. Do not call `AddPasswordSignUpEndpoints`.
3. Map those four groups on one prefix. Do not call `MapPasswordSignUpEndpoints`.
4. Create each user with `UserManager<TUser>` in your admin code. Set `EmailConfirmed` when you create the user, or the default confirmed-account rule blocks sign-in.

```cs recipe
using AuthEndpoints;
using AuthEndpoints.Identity;
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite("Data Source=app.db"));

builder.Services.AddAuthEndpointsIdentity<AppUser, AppDbContext>(options =>
{
    options.User.RequireUniqueEmail = true;
});
builder.Services.AddPasswordSignInEndpoints();
builder.Services.AddPasswordRecoveryEndpoints();
builder.Services.AddAccountManagementEndpoints();
builder.Services.AddCookieSessionEndpoints();
builder.Services.AddTransient<IEmailSender<AppUser>, QueuedIdentityEmailSender>();

var app = builder.Build();
app.UseAuthEndpoints();

var auth = app.MapGroup("/auth");
auth.MapPasswordSignInEndpoints<AppUser>(AuthEndpointsSession.Cookie);
auth.MapPasswordRecoveryEndpoints<AppUser>();
auth.MapCookieSessionEndpoints<AppUser>();
auth.MapAccountManagementEndpoints<AppUser>();

app.Run();

public class AppUser : IdentityUser { }

public class AppDbContext(DbContextOptions<AppDbContext> options) : IdentityDbContext<AppUser>(options) { }

public sealed class QueuedIdentityEmailSender : IEmailSender<AppUser>
{
    public Task SendConfirmationLinkAsync(AppUser user, string email, string confirmationLink)
        => Task.CompletedTask;

    public Task SendPasswordResetLinkAsync(AppUser user, string email, string resetLink)
        => Task.CompletedTask;

    public Task SendPasswordResetCodeAsync(AppUser user, string email, string resetCode)
        => Task.CompletedTask;
}
```

`POST /auth/login` signs an existing user in. `POST /auth/forgotPassword` and `POST /auth/resetPassword` stay available. `POST /auth/register` is not mapped.

`POST /manage/password` can set a first password after sign-in and step-up. It returns `404` when password sign-in is not mapped. This host maps password sign-in, so the route is present.

## Leave these maps off

- External sign-in. A verified provider email creates an account. There is no option to stop that. See [External OAuth](/modules/external-oauth#security-behavior).
- Email-code sign-up. `AllowSignUp` defaults to `false`. Leave it `false` if you map email-code sign-in. See [Sign in with an emailed code](/guides/email-code).
- Passkey register. `MapPasskeySignInEndpoints` maps `POST /passkeys/register`, which creates an account. Login without that route is in [Passkeys](/modules/passkeys#map).
