Paths use the facade defaults: `IdentityPath` is `/identity`, `PasskeyPath` is `/account`, and `Jwt.Path` is `/auth`. External OAuth routes have no default prefix. The table uses `/auth/external`, the prefix from the examples.

Column meanings:

- **Auth**: the route requires a signed-in user.
- **CSRF**: the route runs the antiforgery filter. See [Antiforgery (CSRF) rules](/modules/csrf).
- **ReAuth**: the route requires a fresh step-up proof. See [ReAuth module](/modules/reauth).
- **Rate limit**: the policy name without the `AuthEndpoints.` prefix. See [Rate-limit policies](/modules/rate-limits).

## Passkeys

Mapped by `MapPasskeyEndpoints` under `{prefix}/passkeys`. The facade maps it under `PasskeyPath` unless `Passkeys.Enabled` is `false`.

| Method | Path | Auth | CSRF | ReAuth | Rate limit |
| --- | --- | --- | --- | --- | --- |
| `POST` | `/account/passkeys/creationOptions` | Yes | Yes | Yes | `Passkey.ObtainOptions` |
| `POST` | `/account/passkeys/requestOptions` | | Yes | | `Passkey.ObtainOptions` |
| `POST` | `/account/passkeys/register/options` | | Yes | | `Passkey.ObtainOptions` |
| `POST` | `/account/passkeys/register` | | Yes | | `Passkey.Register` |
| `POST` | `/account/passkeys/login` | | Yes | | `Login` |
| `POST` | `/account/passkeys/` | Yes | Yes | Yes | `Passkey.Register` |
| `GET` | `/account/passkeys/` | Yes | | | |
| `PATCH` | `/account/passkeys/` | Yes | Yes | Yes | |
| `DELETE` | `/account/passkeys/{credentialIdUrl}` | Yes | Yes | Yes | |

Signed-in routes accept the application cookie, Identity bearer, and JWT. A ReAuth credential alone does not. The CSRF column means the antiforgery filter is attached. Anonymous ceremonies always validate a token. Signed-in changes skip that check only for an `Authorization: Bearer` token that is not read from a cookie. See [Antiforgery (CSRF) rules](/modules/csrf).

## Building blocks

3.4.0 adds smaller maps. The tables above are the routes each composite still maps. Call a smaller map when one prefix should omit register, login, or passkey management. Register the matching `Add*` method. When that call is missing, the map writes a warning on the `AuthEndpoints` category and still adds the routes. The message is `{AddMethod} was not called before {MapMethod}.`

| Map | Add | What it maps |
| --- | --- | --- |
| `MapPasswordEndpoints` | `AddPasswordEndpoints` | `POST /register`, `POST /forgotPassword`, `POST /resetPassword`, and `POST /login` for `PasswordLoginMode.Cookie` or `PasswordLoginMode.IdentityBearer`. `PasswordLoginMode.None` omits `/login`. Also maps confirm-email when that endpoint name is new. The default mode is `Cookie`. |
| `MapCookieSessionEndpoints` | `AddCookieSessionEndpoints` | `POST /logout`, `GET /csrfToken` |
| `MapBearerSessionEndpoints` | `AddBearerSessionEndpoints` | `POST /refresh`, `POST /logout` |
| `MapJwtPasswordEndpoints` | `AddJwtEndpoints` | `POST /create` |
| `MapJwtSessionEndpoints` | `AddJwtEndpoints` | `POST /refresh`, `GET /verify`, `POST /logout`, `GET /csrfToken` |
| `MapPasskeySignInEndpoints` | `AddPasskeyEndpoints` | `POST /passkeys/requestOptions`, `POST /passkeys/register/options`, `POST /passkeys/register`, `POST /passkeys/login`. Maps confirm-email on the parent group when that name is new. |
| `MapPasskeyManagementEndpoints` | `AddPasskeyEndpoints` | `POST /passkeys/creationOptions`, `POST /passkeys/`, `GET /passkeys/`, `PATCH /passkeys/`, `DELETE /passkeys/{credentialIdUrl}` |
| `MapConfirmEmailEndpoints` | `AddAccountAbuseRateLimiting` | `GET /confirmEmail`, `POST /resendConfirmationEmail`. The warning text is `AddAccountAbuseRateLimiting was not called before MapConfirmEmailEndpoints.` |
| `MapAccountManagementEndpoints` | `AddAccountManagementEndpoints` | `POST /confirmIdentity`, `GET /manage/authMethods`, `GET` and `POST /manage/2fa`, `GET` and `POST /manage/info`. Maps confirm-email when that name is new. Maps `POST /confirmIdentity/passkeyOptions` when `AddPasskeyEndpoints` was called. |

The composites are those pieces:

| Composite | Pieces |
| --- | --- |
| `MapIdentityManagementApi` | `MapPasswordEndpoints` with `PasswordLoginMode.None`, `MapConfirmEmailEndpoints`, and `MapAccountManagementEndpoints`. Passkey reauthentication options stay mapped. |
| `MapCookieAuthEndpoints` | Cookie `POST /login` plus `MapCookieSessionEndpoints` |
| `MapBearerAuthEndpoints` | Identity bearer `POST /login` plus `MapBearerSessionEndpoints` |
| `MapJwtAuthEndpoints` | `MapJwtPasswordEndpoints` plus `MapJwtSessionEndpoints` |
| `MapPasskeyEndpoints` | Passkey sign-in and management on one `/passkeys` group. This composite does not map confirm-email. |

`AddCookieAuthEndpoints` registers password, cookie session, and account management. `AddBearerAuthEndpoints` registers password, bearer session, and account management. `AddAuthEndpointsIdentity<TUser, TContext>` registers Identity API endpoints, EF stores, default token providers, authorization, and antiforgery. `RequireConfirmedAccount` starts as `true` and `Stores.SchemaVersion` starts as version 3. The configure callback runs after those defaults.

Confirm-email is mapped once per name. The default is `AuthEndpointsEndpointNames.ConfirmEmail<TUser>()` (`MapIdentityManagementApi-{TUser}-confirmEmail`). A later map with the same name leaves the first route in place. `RequireAuthEndpointsUser()` authorizes the application cookie, Identity bearer, and JWT bearer schemes that are registered. A ReAuth cookie or token is not a sign-in.

An email-code host that skips password routes is in [Compose a custom auth stack](/composables/recipes#email-code-only).
