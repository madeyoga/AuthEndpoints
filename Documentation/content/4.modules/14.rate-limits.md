Most policies partition by client IP address. `AuthEndpoints.ConfirmIdentity.EmailCode` partitions by the signed-in user id and falls back to the client IP when that id is absent. A rejected request returns `429`. Policies take effect only when the pipeline calls `UseRateLimiter()`. `UseAuthEndpoints` calls it. Call `UseRateLimiter()` after `UseAuthentication()` so the email-code step-up policy can read the user id.

## Policies

| Policy constant | Limiter | Limit |
| --- | --- | --- |
| `AuthEndpoints.Login` | Token bucket | 10 tokens. 2 tokens are added every 10 seconds. |
| `AuthEndpoints.AccountAbuse` | Fixed window | 10 requests per minute |
| `AuthEndpoints.ConfirmIdentity` | Fixed window | 20 requests per minute |
| `AuthEndpoints.ConfirmIdentity.EmailCode` | Fixed window | 3 requests per minute, partitioned by user id (client IP when the user id is absent) |
| `AuthEndpoints.Passkey.ObtainOptions` | Fixed window | 5 requests per minute |
| `AuthEndpoints.Passkey.Register` | Fixed window | 3 requests per minute |
| `AuthEndpoints.EmailCode.Send` | Fixed window | `EmailCode.SendsPerIpPerMinute` requests per minute. The default is 5. |

No policy queues requests. The `QueueLimit` is `0`.

## Routes per policy

| Policy | Routes |
| --- | --- |
| `AuthEndpoints.Login` | Cookie and Identity bearer `POST /login`, JWT `POST /create` and `POST /refresh`, passkey `POST /passkeys/login`, external `GET /login/{provider}` and `GET /link/{scheme}`, email-code `POST /emailCode/verify` |
| `AuthEndpoints.EmailCode.Send` | `POST /emailCode/send` |
| `AuthEndpoints.AccountAbuse` | `POST /register`, `POST /resendConfirmationEmail`, `POST /forgotPassword`, `POST /resetPassword`, `POST /manage/password` |
| `AuthEndpoints.ConfirmIdentity` | `POST /confirmIdentity`, `POST /confirmIdentity/passkeyOptions` |
| `AuthEndpoints.ConfirmIdentity.EmailCode` | `POST /confirmIdentity/emailCode/send` |
| `AuthEndpoints.Passkey.ObtainOptions` | `POST /passkeys/creationOptions`, `POST /passkeys/requestOptions`, `POST /passkeys/register/options` |
| `AuthEndpoints.Passkey.Register` | `POST /passkeys/register`, `POST /passkeys/` |

Identity bearer `POST /refresh` has no rate limit.

`POST /emailCode/send` and `POST /confirmIdentity/emailCode/send` also enforce `ResendCooldown` (default 60 seconds) and `MaxSendsPerEmail` per `SendWindow` (default 5 sends per hour). Both limits are per address and per stored purpose, so a step-up send does not block a sign-in send. Those checks return the normal `200` send body and do not return `429`. The `429` on `POST /emailCode/send` is only the per-IP window. The `429` on `POST /confirmIdentity/emailCode/send` is the per-user window.

## Registration

| DI call | Policies it registers |
| --- | --- |
| `AddCookieAuthEndpoints` | `Login`, `AccountAbuse`, `ConfirmIdentity` |
| `AddBearerAuthEndpoints` | `Login`, `AccountAbuse`, `ConfirmIdentity` |
| `AddPasswordEndpoints` | `Login`, `AccountAbuse` |
| `AddAccountManagementEndpoints` | `AccountAbuse`, `ConfirmIdentity` |
| `AddAccountAbuseRateLimiting` | `AccountAbuse` |
| `AddConfirmIdentityRateLimiting` | `ConfirmIdentity` |
| `AddJwtEndpoints` | `Login`, `AccountAbuse`, `ConfirmIdentity` |
| `AddPasswordAuth` | `Login`, `AccountAbuse`, `ConfirmIdentity`. Also `Passkey.ObtainOptions` and `Passkey.Register` when `Passkeys.ServerDomain` is set. |
| `AddPasskeyEndpoints` | `Login`, `AccountAbuse`, `ConfirmIdentity`, `Passkey.ObtainOptions`, `Passkey.Register` |
| `AddExternalAuthEndpoints` | `Login` |
| `AddEmailCodeSendEndpoints` | `EmailCode.Send`, `ConfirmIdentity.EmailCode` |
| `AddEmailCodeSignInEndpoints` | `Login` |
| `AddEmailCodeEndpoints` | `Login`, `EmailCode.Send`, `ConfirmIdentity.EmailCode` |
| `AddConfirmIdentityEmailCodeRateLimiting` | `ConfirmIdentity.EmailCode` |

Each policy is registered once, even when several calls add it.
