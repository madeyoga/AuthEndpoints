`AuthEndpoints.OpenIddict` (preview) turns an AuthEndpoints app into an OAuth 2.0 authorization server, built on OpenIddict 7.7. The core `AuthEndpoints` package does not change and has no OpenIddict dependency.

The package [README](https://github.com/madeyoga/AuthEndpoints/tree/main/src/AuthEndpoints.OpenIddict#readme) covers setup, the consent step, certificates, dynamic registration, and every setting.

## In short

```csharp
builder.Services.AddAuthEndpointsOpenIddict<AppUser, AppDbContext>(options =>
{
    options.Issuer = new Uri("https://auth.example.com/");
    options.Audience = "https://api.example.com/";
    options.Scopes.Add("api");
    options.LoginUrl = "https://app.example.com/sign-in";
    options.ConsentUrl = "https://app.example.com/oauth/consent";
    options.Certificates.Path = "/var/lib/myapp/oauth-keys";
});

// OnModelCreating
builder.UseAuthEndpointsOpenIddict<AppUser>();

app.MapAuthEndpointsOpenIddict();
app.MapOAuthConsentEndpoints();
```

- Authorization code + PKCE (S256 only), rotating refresh tokens with no reuse leeway, 15-minute reference access tokens, revocation.
- `/connect/authorize` sends signed-out users to `LoginUrl` with a `returnUrl` on this server, and signed-in users to `ConsentUrl?request={id}`. Your page approves or denies through `MapOAuthConsentEndpoints` or `IOAuthConsentService`.
- The token subject defaults to the Identity user id. Replace it with `IOAuthPrincipalFactory`.
- Every code exchange and refresh checks the approving user again (exists, can sign in, not locked out, same security stamp). A failed check revokes the grant.
- Dynamic client registration and protected resource metadata are off by default.
- HTTPS, resource (audience) validation, and per-client resource permissions are on by default.

## Relation to external sign-in

[External OAuth](/modules/external-oauth) signs users in to your app with another provider. This package makes your app the provider. A user who signed in with a cookie-mode external provider can approve an OAuth client like any other signed-in user.

## Limitations

This is a preview. OpenID Connect (ID tokens, `userinfo`, logout, and the `email`, `email_verified`, and `amr` claims) is not supported yet, and only this server can validate its access tokens. The package [README](https://github.com/madeyoga/AuthEndpoints/tree/main/src/AuthEndpoints.OpenIddict#limitations) lists every known gap. Remaining work is tracked in [#389](https://github.com/madeyoga/AuthEndpoints/issues/389).
