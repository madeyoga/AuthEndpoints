ReAuth (step-up) confirms the user's identity before sensitive mutations. It is included when you map [Identity management](/modules/identity-management) (with antiforgery in the management map).

## Schemes and header

| Piece | Value |
| --- | --- |
| Cookie scheme | `AuthEndpoints.ReAuth` (default 5 minutes, `ReAuth.Lifetime`) |
| Bearer scheme | `AuthEndpoints.ReAuth.Bearer` |
| Header | `X-AuthEndpoints-Reauth` with `reauthToken` |
| Policy | `ReAuthPolicy` (no authentication schemes) |

## Routes

Mapped with management (facade under `/identity`). Both `POST` routes require authorization and the `AuthEndpoints.ConfirmIdentity` rate limit. `MapIdentityManagementApi` also adds antiforgery to both, so send `RequestVerificationToken` on each:

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/manage/authMethods` | Available step-up methods |
| `POST` | `/confirmIdentity` | Exactly one proof; CSRF when mapped via management |
| `POST` | `/confirmIdentity/passkeyOptions` | WebAuthn options for passkey step-up; CSRF when mapped via management |

### ConfirmIdentity proof

Provide **exactly one** of:

- `password`
- `twoFactorCode`
- `twoFactorRecoveryCode`
- `credentialJson` (passkey assertion)

On success: ReAuth cookie for browser clients; `reauthToken` for API clients using the header. Cookie and token share the same lifetime.

The step-up credential is an extra proof on top of a sign-in. It is never a sign-in by itself. `ReAuthPolicy` adds no authentication schemes, so ASP.NET Core does not merge the ReAuth principal into `HttpContext.User`. The requirement authenticates the ReAuth cookie and then `X-AuthEndpoints-Reauth`, and succeeds only when that proof has `Reauth=true` and the same user id as the signed-in user. A request with only the cookie or the header is `401`. A signed-in user with no proof, an expired proof, or a proof issued to someone else is `403` when the endpoint's other authorization already authenticated the sign-in.

`.RequireReauth()` alone does not pull in the default authorization policy, and `ReAuthPolicy` adds no authentication schemes. The authentication middleware's default scheme is the sign-in when it succeeds. `AddIdentityApiEndpoints` uses a composite scheme, so that is the application cookie or the Identity bearer token. A signed-in caller with no proof, an expired proof, or a proof for someone else gets `403`. If that principal is missing, the requirement authenticates the registered application-cookie, Identity bearer, and JWT bearer schemes and uses the first success. A JWT on a host whose default scheme is the Identity composite is in that fallback: a valid token with no matching proof is `401`, because the authorization middleware itself did not authenticate a scheme. Pass the JWT scheme to `.RequireAuthorization(...)` when a missing proof should be `403`. Account management and passkey routes already do that for every registered sign-in scheme.

## Lifetime

Default is **5 minutes**, non-persistent, no sliding expiration. Set `AuthEndpointsOptions.ReAuth.Lifetime` (a `TimeSpan`) on the facade, or `IOptions<AuthEndpointsReAuthOptions>` on a composable host. One value drives confirm `ExpiresUtc`, cookie `ExpireTimeSpan`, and `reauthToken` expiry.

Valid range: 1 minute through 60 minutes. Startup rejects zero, negative, over 60 minutes, and `InfiniteTimeSpan`.

```cs
builder.Services.AddAuthEndpoints<AppUser, AppDbContext>(o =>
{
    o.ReAuth.Lifetime = TimeSpan.FromMinutes(2);
});
```

## Protecting host endpoints

```cs
builder.Services.AddCookieAuthEndpoints(); // or AddBearerAuthEndpoints — registers ReAuth schemes

app.MapPost("/billing/update", handler)
    .RequireAuthorization()
    .RequireReauth();
```

## Typical client flow

1. `GET /identity/manage/authMethods`
2. Collect proof (password, 2FA, or passkey via `POST /identity/confirmIdentity/passkeyOptions` with CSRF)
3. `POST /identity/confirmIdentity` with CSRF
4. Retry the sensitive action with ReAuth cookie and/or `X-AuthEndpoints-Reauth`

## Where ReAuth is required

- Manage 2FA / info mutations
- Passkey add, rename, delete, and creation options
- Any host endpoint with `.RequireReauth()`
