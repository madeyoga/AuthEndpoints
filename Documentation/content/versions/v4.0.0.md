### AuthEndpoints, External.OAuth, GitHub, and Google

4.0.0 ships `AuthEndpoints`, the `AuthEndpoints.External.OAuth` forwarding shim, `AuthEndpoints.OAuth.GitHub`, and `AuthEndpoints.OAuth.Google` together. The shim and the provider packages depend on `AuthEndpoints` with the range `[4.0.0, 5.0.0)`.

`AddPasswordAuth` and `MapPasswordAuth` are the new password facade. Cookie is the default session. JWT is allowed. Identity bearer stays on `AddAuthEndpoints`. `AddAuthEndpoints` and `MapAuthEndpoints` stay the 3.4.1 facade: same options, same routes, not obsolete. They do not gain 4.0-only behaviour except opt-in JWT body transport, the unknown-email hash verify on `POST /create`, and JWT refresh hardening.

New building blocks:

- One sign-in completer, selected with `AuthEndpointsSession` or a completer name. The 3.x per-method completers are obsolete and still run when a host registers one and the map passes no session.
- Email-code step-up on `POST /confirmIdentity/emailCode/send` for users with no password, authenticator, or passkey. External logins do not block it. `UseEmailCodes()` hosts add a migration for the `Purpose` column before deploying.
- JWT `RefreshTokenTransport.Body` for clients with no cookie jar. Both transports rotate refresh tokens, revoke the family on reuse, enforce an absolute lifetime, bind the token to the security stamp, and revoke the family on logout. `UseRefreshToken()` hosts add a migration for `AbsoluteExpiresAt`.
- `POST /manage/password` sets a first password. The frozen facade does not map it.
- Register, forgot-password, resend, email-code send, and passkey registration options return the same response for known and unknown emails.

`MapGitHubAuthEndpoints` and `MapGoogleAuthEndpoints` are removed. Map `MapExternalAuthProvider` or `MapExternalAuthEndpoints`. A missing `Add*` throws at map time. `AuthEndpoints.External.OAuth` below 4.0.0 fails the build with `AE4000`.

### Upgrading from 3.4.1

Follow [Upgrade to 4.0](/guides/upgrading-to-4). B1, B2, B14, and B15 are withdrawn. Every other row from B3 through B22 has a migration step on that page.
