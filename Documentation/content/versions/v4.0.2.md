### AuthEndpoints

On a host with email-code sign-in only, `POST /confirmIdentity/emailCode/send` now returns `404` instead of `500`, and `authMethods.emailCode` goes from `true` to `false`. The send route and the `AuthEndpoints.ConfirmIdentity.EmailCode` rate-limit policy belong to email-code send. Sign-in alone left the route mapped without that policy, so each signed-in call to it returned `500`. `POST /confirmIdentity` with `{ "emailCode" }` on that host returns `400` with title `EmailCodeProofUnavailable` instead of `401`.

Hosts that want the step-up send call `AddEmailCodeSendEndpoints` or `AddEmailCodeEndpoints`.

No host change is required for apps that already add email-code send. This release adds no database migration.
