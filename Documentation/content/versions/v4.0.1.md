### AuthEndpoints

Mapping a route group once logged a duplicate-route warning for every route, with the same map named twice. `MapGroup("/account").MapCookieSessionEndpoints<TUser>()` logged `MapCookieSessionEndpoints and MapCookieSessionEndpoints both map POST /account/logout.` and the same for `GET /account/csrfToken`. The app reads a group's endpoints more than once as it starts, and each read looked like another map. A group mapped once stays quiet. Two maps that share a method and path still log once.

- `MapGroup(...).MapCookieSessionEndpoints<TUser>()` and the other group maps no longer warn about their own routes
- Cookie and bearer `POST /logout` on one prefix still warns once
- Cookie `POST /login` from `MapPasswordEndpoints` and `MapCookieAuthEndpoints` on one prefix still warns once

No host change is required. This release adds no database migration.
