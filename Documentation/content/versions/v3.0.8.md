### AuthEndpoints

Passkey login `requestOptions` takes JSON `{ "email" }` instead of `?username=`. Unknown or empty email still returns 200 usernameless options. `MapPasskeyEndpoints` fails fast at map time if the user store lacks passkey or email support.

Signed-in passkey add rejects an attestation whose user id is not the current user and does not store it. Missing credentials on delete and rename return 404. Invalid credential ids and a ceremony that is not underway return validation problems. Add accepts optional `name`; list and add include `createdAt`. Register and login apply lockout and `CanSignInAsync` before completing sign-in: register that cannot sign in still returns the credential id with no session, and login returns 401.

- Passkey login `requestOptions` takes JSON `{ "email" }` instead of `?username=`
- Unknown or empty email still returns 200 usernameless options
- `MapPasskeyEndpoints` fails fast at map time if the user store lacks passkey or email support
- Signed-in add rejects a mismatched attestation user id and does not store it
- Missing credentials on delete and rename return 404
- Register and login apply lockout and `CanSignInAsync` before completing sign-in
