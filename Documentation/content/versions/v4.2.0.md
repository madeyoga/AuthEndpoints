### AuthEndpoints

**Bearer schemes that skip the CSRF check.** `AuthEndpointsAntiforgeryOptions.BearerSchemes` lists the authentication schemes that let a request skip the check of `RequireAntiforgery()`. The default is `Identity.Bearer` and the JWT bearer scheme (`Bearer`), the same schemes as before. A host or package with its own header-based token scheme adds it with `services.Configure<AuthEndpointsAntiforgeryOptions>(o => o.BearerSchemes.Add("MyTokenScheme"))`. The rest of the rule is unchanged: the request must carry `Authorization: Bearer`, the application cookie must not authenticate it, and a scheme whose handler is a cookie handler is ignored. `POST /confirmIdentity` uses the same list to decide whether to set the ReAuth cookie.

**Routes that always need the token.** `RequireAntiforgery(allowBearer: false)` on a route or route group requires the antiforgery token from every caller, including one with a valid bearer token. Use it on routes a token must never call on its own, such as consent approval or account deletion. `RequireAntiforgery()` is `RequireAntiforgery(allowBearer: true)`.

**Agent skill in the package.** The `authendpoints` [Agent Skill](https://agentskills.io) now ships in the NuGet package. `dotnet restore` places it under `~/.nuget/packages/authendpoints/4.2.0/skills/authendpoints/`, matched to this version. See [Coding agents](/getting-started/ai-agents).

This release includes the 4.1.1 fix: password reset and email sign-in codes are sent only to the account's stored email address.

No host change is required. This release adds no database migration.
