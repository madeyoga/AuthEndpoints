### AuthEndpoints

`AddPasswordAuth<TUser, TRole, TContext>` registers Identity roles before the EF stores. `IUserStore<TUser>` supports roles, `RoleManager<TRole>` resolves, and sign-in uses `UserClaimsPrincipalFactory<TUser, TRole>`, so a role claim is present after password sign-in. The two-type `AddPasswordAuth<TUser, TContext>` still registers no roles.

`TContext` is `IdentityDbContext<TUser, TRole, TKey>` or the equivalent. Do not chain `.AddRoles<TRole>()` after the two-type overload.

No host change is required when the app does not use roles. This release adds no database migration.
