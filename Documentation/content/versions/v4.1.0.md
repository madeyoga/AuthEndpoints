### AuthEndpoints

**Active sessions.** Users can list where they are signed in and sign out other browsers or devices, for cookie and JWT sessions. It is off by default. Turn it on with `builder.UseActiveSessions()` in `OnModelCreating`, `AddActiveSessions<TUser, TContext>()`, and `MapActiveSessionEndpoints<TUser>()`. That maps `GET /auth/sessions`, `DELETE /auth/sessions/{id}`, and `POST /auth/sessions/revokeOthers`. Revoking needs a recent re-authentication. Identity bearer tokens are not supported, and the app fails at startup if it maps them while active sessions are on.

**Roles on the password facade.** `AddPasswordAuth<TUser, TRole, TContext>` registers Identity roles before the EF stores, so a host that uses roles can stay on the facade.

**External sign-in providers.** `GET /auth/external/providers` returns `{ "scheme", "displayName" }` for each registered provider, in registration order. `AddExternalAuthEndpoints<TUser>()` maps the account routes when no provider is registered yet; the providers and logins lists then return `[]`.

**Two-factor settings.** `GET /auth/manage/2fa` returns `recoveryCodesLeft` next to `isTwoFactorEnabled`. Enabling two-factor keeps the user's step-up confirmation with its original expiry: the ReAuth cookie is reissued, and a token sent in `X-AuthEndpoints-Reauth` comes back renewed in the same response header. Send the renewed token on the next request. A cross-origin browser client can read it only when the CORS policy exposes that header.

**JWT signing keys.** Startup validation requires the key property that signing reads for the selected algorithm. A host that sets `Rsa` with only `Certificate`, `X509` with only `RsaKey`, or `Ecdsa` without `EcdsaKey` fails at startup with an error that names the property to set, for example `RsaKey is required when Algorithm is Rsa. Set SimpleJwtOptions.SigningOptions.RsaKey.`

No host change is required unless the selected JWT algorithm is missing its key. Hosts that do not turn on active sessions need no database migration. Turning on active sessions needs a migration that adds the `AuthEndpointsActiveSessions` table and, with JWT, a nullable `SessionId` column on refresh tokens.
